# Go Wasm plugin example

This is a bare-bones Typst plugin, written in Go.

## Compile

To compile this example, you need the [TinyGo compiler](https://tinygo.org/). Then, run the command:

```sh
tinygo build -target=wasm-unknown -o hello.wasm
```

The `-target=wasm-unknown` flag is similar to `-target wasm32-unknown-unknown` in Rust and it tells the compiler to generate a WebAssembly binary that does not depend on any specific environment.

## Compile with wasip1

If you want to build with WASI, use the `wasip1` target:

```sh
GOOS=wasip1 GOARCH=wasm tinygo build -o hello.wasm -scheduler=none
```

Then, stub the resulting binary:

```sh
wasi-stub hello.wasm -o hello.wasm
```

## Build with Typst

Simply run `typst compile hello.typ`, and observe that it works!

## Further explanation

### The none scheduler

When targeting WASI and building with [TinyGo v0.43.0](https://github.com/tinygo-org/tinygo/releases/tag/v0.43.0) or above, the CBOR `complex_data` function only works when [`-scheduler=none`](https://tinygo.org/docs/reference/usage/important-options/#:~:text=Binaryen%E2%80%99s%20Asyncify%20Pass%2E-,scheduler=none,-The%20none%20scheduler) is specified. Otherwise, you will encounter the following error when calling `p.complex_data(encoded)`:

> error: plugin panicked: wasm `unreachable` instruction executed

<details><summary>More details about this error</summary>

The traceback[^traceback] is shown as below.

[^traceback]: The traceback was generated by calling `p.complex_data(encoded)` with a JavaScript script that simulates Typst's protocol.

```js
RuntimeError: unreachable
    at main.runtime.runtimePanicAt
    at main.runtime.nilPanic
    at main.runtime.setupDeferFrame
    at main.(*sync.Map).Load
    at main.github.com/fxamacker/cbor/v2.getTypeInfo
    at main.complex_data
    at …
```

The traceback implies that the error originated from the runtime generated by TinyGo, rather than from our Go code. This is likely related to the [panic recovery feature that was added for Wasm](https://github.com/tinygo-org/tinygo/pull/5550) in TinyGo v0.43.0.

</details>

The `-scheduler=none` option disables scheduler support, which means that goroutines and channels are not available in your Go code. However, for Typst Wasm plugins, scheduler support probably won't be useful anyway.

If you truly need scheduler support or find the above explanation incorrect, please [open an issue](https://github.com/typst-community/wasm-minimal-protocol/issues/new).
